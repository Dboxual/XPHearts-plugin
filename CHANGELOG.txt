--------------------------------------------------------------------------------
  [1.3.7] - 2026-05-14  [experimental/soulbound-multiplier]
--------------------------------------------------------------------------------

CHANGED
  - Soulbound Ledger now uses two materials depending on charge state:
      Charging  (0 to max-1 kills) → WRITABLE_BOOK (Book & Quill)
      Fully charged                → ENCHANTED_BOOK (auto-converted on reaching full charge)
    The conversion to ENCHANTED_BOOK happens in onMobDeath the moment the
    final charge is applied, so the player sees the item visually upgrade in
    their hand. Only the ENCHANTED_BOOK form can be right-clicked to consume.

  - Newly crafted Soulbound Ledgers start as WRITABLE_BOOK (uncharged).

  - Right-click cancel for WRITABLE_BOOK charm: PlayerInteractEvent is cancelled
    in EquipmentSlot.HAND (main hand) whenever an uncharged charm is detected,
    preventing the vanilla Book & Quill editor from opening. Offhand right-clicks
    are already cancelled by the existing charm handler.

MIGRATION
  - v1.3.6 ENCHANTED_BOOK ledger that is NOT fully charged → reverts to
    WRITABLE_BOOK on the next mob kill or offhand right-click, preserving charge.
  - Fully charged ledger (any material) → stays or converts to ENCHANTED_BOOK.
  - Legacy EMERALD charms → WRITABLE_BOOK if uncharged, ENCHANTED_BOOK if full.
  - All migration is PDC-based (charm_id = "xp_multiplier_charm"); no material
    check is used for identity.

FIXED
  - EquipmentSlot.MAIN_HAND → EquipmentSlot.HAND (Bukkit enum constant name).

TECHNICAL
  - CharmManager: createCharm() reverted to WRITABLE_BOOK, no ItemFlag on fresh
    items. needsMaterialUpgrade()/migrateCharm() removed; replaced by single
    ensureCorrectMaterial(ItemStack) — picks target material by charge vs
    charge-required, rebuilds only when needed, adds HIDE_ENCHANTS for
    ENCHANTED_BOOK only.
  - CharmListener.onMobDeath: ensureCorrectMaterial() called after setCharge()
    before setItemInOffHand().
  - CharmListener.onRightClick: reordered to check EquipmentSlot.HAND first;
    WRITABLE_BOOK charm in main hand → event cancelled, return. Offhand section
    now calls ensureCorrectMaterial() after isCharm() guard, before the
    isFullyCharged() consume gate.
  - VERSION bumped to 1.3.7.

--------------------------------------------------------------------------------
  [1.3.6] - 2026-05-14  [experimental/soulbound-multiplier]
--------------------------------------------------------------------------------

FIXED
  - Soulbound Ledger: switched material from WRITABLE_BOOK to ENCHANTED_BOOK.
    Players could previously open a Book & Quill editor when right-clicking
    the ledger in the main hand. ENCHANTED_BOOK has no book-open behavior in
    vanilla and already carries the enchanted glint natively — no extra
    Enchantment.UNBREAKING needed.

CHANGED
  - Legacy charm migration: charms created before v1.3.6 (EMERALD or
    WRITABLE_BOOK) automatically upgrade to ENCHANTED_BOOK the next time
    they receive a charge tick (mob kill in offhand). Charge value is
    preserved. Identity remains PDC-based (charm_id = "xp_multiplier_charm"),
    so all old items continue to function until they are migrated.

TECHNICAL
  - CharmManager: Material.WRITABLE_BOOK → Material.ENCHANTED_BOOK in
    createCharm(). Enchantment.UNBREAKING addEnchant() call removed (native
    glint). HIDE_ENCHANTS flag kept to suppress any stored-enchantment tooltip.
    Added needsMaterialUpgrade(ItemStack) and migrateCharm(ItemStack) — creates
    a fresh ENCHANTED_BOOK charm preserving the current charge, PDC tag,
    HIDE_ENCHANTS flag, and max-stack-size 1.
    Enchantment import removed.
  - CharmListener.onMobDeath: after setCharge(), calls needsMaterialUpgrade()
    and replaces the offhand item via migrateCharm() before setItemInOffHand().
    No Material import required in CharmListener.
  - config.yml: section comment updated ("Book & Quill" → "Enchanted Book").
  - VERSION bumped to 1.3.6.

  [build] - 2026-05-08

BUILD
  - Build output restructured to versioned release folders.

  [1.3.4] - 2026-05-08
--------------------------------------------------------------------------------

CHANGED
  - /withdraw amount is now configurable via multiplier.withdraw-amount in
    config.yml (default: 1.0). Supports any positive decimal (0.5, 1.0, 1.5…).
    The Multiplier Token item displays and stores the configured amount in NBT.
    Applying the token gives exactly the amount stored in it, so tokens created
    with different withdraw-amount settings always apply the right value.

  - Minimum multiplier check updated: player must have >= (1.0 + withdraw-amount)
    before withdrawing. Error message shows the required threshold.

  - Token name and lore now reflect the actual amount ("+0.5x Multiplier Token",
    "Contains: +0.5x XP Multiplier", etc.).

TECHNICAL
  - CharmManager: tokenAmountKey (NamespacedKey) added; createWithdrawToken()
    now takes a double amount, stores it in PDC (PersistentDataType.DOUBLE),
    and uses it in the display name and lore. getTokenAmount() reads the stored
    double (falls back to 1.0 for tokens created before this version).
    getWithdrawAmount() reads config; fmt() helper added.
  - CharmListener: token right-click now calls getTokenAmount() instead of
    hardcoded +1.0. Message updated to show the token's amount.
  - WithdrawCommand: all hardcoded 1.0 / 2.0 values replaced with
    getWithdrawAmount(); input validation added for misconfigured values.
  - config.yml: withdraw-amount: 1.0 added under multiplier section.
  - VERSION bumped to 1.3.4.

  [1.3.3] - 2026-05-08
--------------------------------------------------------------------------------

ADDED
  - /withdraw command
      Players with multiplier >= 2.0x can run /withdraw to extract exactly
      1.0x as a tradeable Multiplier Token (NETHER_STAR with custom NBT).
      The token is placed in the player's inventory. If the inventory is full,
      the operation is rolled back and an error is shown.
      To apply a token: hold it in offhand and right-click.
      Permission: xphearts.withdraw (default: true — all players).

  - Hostile-mob-only charm charging (allow-passive-mobs config)
      By default, only hostile mobs (implements Monster interface: zombies,
      skeletons, creepers, spiders, blazes, etc.) charge the XP Multiplier
      Charm. Set allow-passive-mobs: true to allow any mob kill to charge it.
      The XP multiplier bonus still applies to all kills regardless of this
      setting.

CHANGED
  - Charm consume now grants +0.5x multiplier (was +1.0x).
      Multiplier values are now stored as doubles. Existing integer values
      in data.yml are loaded correctly via getDouble() for backward compat.

  - /xpmultiplier set now accepts decimal values (e.g. set <player> 2.5).

  - All multiplier displays updated to use clean formatting:
      2.0 shows as "2x", 1.5 shows as "1.5x", etc.

  - PlaceholderAPI %xphearts_multiplier% and %xphearts_multiplier_raw%
      updated to reflect decimal multipliers.

TECHNICAL
  - PlayerDataManager: Map<UUID, Integer> → Map<UUID, Double>; getMultiplier
    returns double; setMultiplier takes double; max read via getDouble().
  - CharmManager: tokenIdKey added; createWithdrawToken() / isWithdrawToken()
    added. Charm lore updated to "+0.5x".
  - CharmListener: consume logic changed to +0.5; Monster check added for
    charging gate; withdraw token right-click handling added.
  - WithdrawCommand.java added (com.xphearts.command).
  - plugin.yml: withdraw command + xphearts.withdraw permission added.
  - config.yml: allow-passive-mobs: false added under multiplier section.
  - VERSION bumped to 1.3.3; build.gradle.kts / plugin.yml updated to match.

  [1.3.1] - 2026-05-08
--------------------------------------------------------------------------------

FIXED
  - Grindstone XP Bottling: Glass Bottle now MUST be placed in the grindstone's
    second/bottom input slot (slot 1). Inventory fallback removed entirely.
    Placing a bottle anywhere in the player's inventory no longer triggers the
    feature; the bottle must be physically inside the grindstone.

  - Grindstone shift-click: Shift-clicking a Glass Bottle from the player's
    inventory while a grindstone is open now automatically places it into slot 1
    (the second/bottom input slot) if that slot is empty. It will not displace
    an existing item or go into the wrong slot.

  - PrepareGrindstoneEvent now fires a custom result when slot 0 contains an
    enchanted item and slot 1 contains a Glass Bottle. Without this, vanilla
    shows no result (glass bottle is not valid grindstone equipment), so the
    result slot would remain empty and the feature could never activate.

  - Rotten Flesh shift-click: Shift-clicking Rotten Flesh from the player's
    inventory while a furnace, blast furnace, or smoker is open now moves it
    into the furnace input slot (slot 0) directly. Vanilla does not natively
    route Rotten Flesh via shift-click for custom recipes, so this was handled
    with an InventoryClickEvent intercept. Fuel slot and output slot untouched.

TECHNICAL
  - GrindstoneBottling.java: removed OFFHAND_SLOT/NO_BOTTLE constants,
    findPlayerBottleSlot(), decrementPlayerSlot(), and all player-inventory
    fallback logic. Added PrepareGrindstoneEvent handler and separate
    shift-click handler. stripEnchantments() added for result computation.
  - RottenFleshSmelting.java: now implements Listener. Added
    onShiftClickRottenFlesh() event handler.
  - XPHearts.java: fleshSmelting registered as an event listener.
    VERSION bumped to 1.3.1.
  - build.gradle.kts version: 1.3.1 (jar output: XPHearts-1.3.1.jar)
  - plugin.yml version: 1.3.1

  [1.3.0] - 2026-05-08
--------------------------------------------------------------------------------

ADDED
  - Half-heart toggle (half-hearts-enabled in config)
      Setting to false forces health gains to round down to full hearts only.
      Example with false: level 5 = 10 hearts, level 10 = 11 hearts (no 10.5).
      Example with true (default): level 5 = 10.5 hearts (original behavior).

  - Rotten Flesh Smelting feature
      Smelt Rotten Flesh into Leather in a furnace, blast furnace, or smoker.
      Configurable cooking time (default: 200 ticks) and XP reward (default: 0.1).
      Recipe only registers when enabled. Safe to toggle via reload.

CHANGED
  - /xphearts reload now calls reloadFeatures() which handles:
        config reload, smelting recipe re-registration, and health update for
        all online players — all in one command.

  - /xphearts check now shows max hearts from config rather than hardcoded 20.

  - XPHearts.VERSION constant added (was an inline string).
      PlaceholderAPI expansion now uses this constant instead of a stale literal.

FIXED
  - Grindstone XP Bottling completely rewritten.
      Root cause: vanilla may prevent placing glass bottles in grindstone input
      slots. New logic checks grindstone slots first, then falls back to the
      player's offhand and full inventory automatically.
      Slot interactions now use getItem()/setItem() directly instead of the
      named accessor methods which had inconsistent behavior in Paper 1.21.
      Shift-click handled correctly via event.getRawSlot() check.
      Leftover bottles returned to player if stack > 1 was in a grindstone slot.
      Inventory-full case safely drops all overflow items at the player's feet.

TECHNICAL
  - RottenFleshSmelting.java added (com.xphearts.feature)
  - XPHearts.reloadFeatures() added — single entry point for all reload logic
  - VERSION constant: public static final String VERSION = "1.3.0"
  - build.gradle.kts version: 1.3.0
  - plugin.yml version: 1.3.0
  - jar output: XPHearts-1.3.0.jar

  [1.1.0]
--------------------------------------------------------------------------------

ADDED
  - Grindstone XP Bottling
      Place a glass bottle in offhand/inventory, disenchant at a grindstone,
      click the result to receive a Bottle o' Enchanting instead of XP orbs.
      Config: grindstone-bottling (enabled, bottles-per-dispatch,
      require-dispatch-xp).

  - XP Multiplier Charm system
      Craftable custom item. Hold in offhand while killing mobs to charge it.
      Right-click when fully charged to consume and gain +1x XP multiplier.
      Multiplier persists across restarts. Stored in plugins/XPHearts/data.yml.
      Config: multiplier (enabled, max-multiplier, charge-required,
      mob-kill-charge, apply-to-mob-xp-only, recipe).

  - /xpmultiplier command
      /xpmultiplier                  check own multiplier
      /xpmultiplier set <p> <n>      admin: set a player's multiplier
      /xpmultiplier reset <p>        admin: reset to 1x
      Permission: xphearts.admin (default: op)

TECHNICAL
  - PlayerDataManager.java, CharmManager.java, CharmListener.java added
  - XPMultiplierCommand.java added


--------------------------------------------------------------------------------
  [1.0.0]
--------------------------------------------------------------------------------

ADDED
  - XP Hearts system
      Players gain extra hearts based on XP level.
      Default: every 5 levels = +0.5 hearts. Cap: 20 hearts / 40 HP.
      Health updates on: join, level change, respawn, /xphearts reload.
  - /xphearts check [player]
  - /xphearts reload
  - Configurable: levels-per-half-heart, base-hearts, max-hearts
